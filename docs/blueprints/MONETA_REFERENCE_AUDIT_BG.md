# Moneta Reference Audit — Step 4.0

## Източници

Разгледани са качените reference архиви:

```text
ZipMasterR23(3).zip
Client_REFERENCE_source-only_20260625_1447(7).zip
```

Архивите съдържат предимно Delphi runtime/client файлове: `.bpl`, `.exe`, `.dll`, ресурсни файлове и логове. Те не са подходящи за директно използване в Node.js / Express / Handlebars проекта.

## Правило за безопасност

AutoGrand ERP не използва и не копира Moneta runtime файлове. Reference архивите са само ориентир за:

- модулна структура;
- ERP процеси;
- терминология;
- удобни работни екрани;
- печатни flow-и;
- документни действия.

## Видими ERP модули от reference структурата

Най-важните package имена показват следната логика:

```text
BasePackage.bpl              → ERP основа
NomenclaturesPackage.bpl     → Номенклатури
InventoryPackage.bpl         → Склад
SalesPackage.bpl             → Продажби
PurchasePackage.bpl          → Доставки / покупки
AccountingPackage.bpl        → Счетоводство
CRMPackage.bpl               → CRM / клиенти
ServicePackage.bpl           → Сервиз
VehiclePackage.bpl           → Автомобили
CommercePackage.bpl          → Търговия
DevicePackage.bpl            → Устройства / принтери
FixedAssetPackage.bpl        → Дълготрайни активи
ProductionPackage.bpl        → Производство
ReservPackage.bpl            → Резервации
JobPackage.bpl               → Задачи / операции
AdvancedPackage.bpl          → Разширени функции
TourPackage.bpl              → Турове / маршрути
CustomPackage.bpl            → Клиентски custom слой
```

Това потвърждава, че голяма ERP система не трябва да се пише като един огромен файл, а като ядро плюс отделни модули.

## Идеи, които взимаме като принцип

### 1. Ядро + модули

AutoGrand трябва да има собствено ядро и ясно отделени модули. Не е нужно да копираме структурата 1:1, но принципът е правилен.

### 2. Общ документен модел

Продажби, доставки, трансфери, корекции, сервиз и каса трябва да приличат като поведение:

```text
документ → редове → статус → действия → история → печат
```

### 3. Работни центрове

За реална работа са нужни центрове, не само CRUD списъци:

- трансфери и заявки;
- ценова листа;
- складов център;
- продажбен център;
- доставен център;
- сервизен център;
- касов център.

### 4. Печатни форми

Moneta има логика за избор на печатна форма, принтер, копия и preview. Ние вече започнахме това в Step 3.5, но трябва да го направим общ AutoGrand print engine.

### 5. Действия според статус

Не всички бутони трябва да са активни винаги. Действията трябва да се показват според статус и права.

## Какво НЕ взимаме

- Moneta визуалния стил 1:1;
- бинарни файлове;
- runtime зависимости;
- Delphi package структура като кодова зависимост;
- сложни технически екрани, които не са удобни за AutoGrand потребители.

## AutoGrand интерпретация

AutoGrand трябва да изглежда и да се усеща като собствена система:

- зелен AutoGrand shell;
- по-малко хаос;
- по-ясни бутони;
- по-практични печатни листове;
- по-добра помощ за складовия работник;
- по-лесно търсене;
- по-малко технически термини;
- ясно кой обект какво прави.

## Заключение

Reference архивите потвърждават правилната посока: голямата ERP система трябва да се строи от фундамент, а не само екран по екран. След Step 3.5 вече имаме реален трансферен процес, но следващата правилна работа е да подредим номенклатури, права, артикули, демо база и общи двигатели.
